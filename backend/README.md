# 🛠️ مركز أبو ربيع للمعدات - الخادم ولوحة التحكم

خادم الواجهة الخلفية (Backend) ولوحة تحكم إدارة المتجر لمركز المهندس محمد أبو ربيع للمعدات وصيانة وبيع العدد وقطع الغيار.

---

## 🚀 التقنيات المستخدمة

- **البيئة:** Node.js + Express.js
- **قاعدة البيانات:** MongoDB Atlas (أو Local MongoDB)
- **إدارة النماذج:** Mongoose ODM
- **المصادقة والأمان:** JWT + bcryptjs + Helmet + CORS + express-rate-limit
- **إدارة الملفات والصور:** Multer
- **الواجهة:** صفحات HTML/CSS/JS ثابتة (RTL) تُقدَّم من نفس الخادم

---

## 📁 هيكل المشروع

القاعدة البسيطة: **`frontend/` هو ما يراه الزائر**، **`backend/` هو الخادم**،
و**`data/` هو البيانات والأدوات**. الخادم يقدّم `frontend/` فقط؛ لا يُكشف
`backend/` ولا `data/` للمتصفح أبداً.

```text
abu_rabie/
```

## ⚡ التشغيل محلياً

### 1. تثبيت الحزم

```bash
cd backend
npm install
```

### 2. ضبط متغيرات البيئة

انسخ `backend/.env.example` إلى `backend/.env` ثم عدّل القيم:

```bash
cp .env.example .env
```

أهم القيم:

| المتغير | الوصف |
|---------|-------|
| `MONGODB_URI` | رابط MongoDB Atlas أو MongoDB محلي |
| `JWT_SECRET` | **32 حرفاً على الأقل** في الإنتاج |
| `ADMIN_PASSWORD` | كلمة مرور لوحة التحكم (يرفض سكربت التعبئة إنشاء الحساب بالقيمة `admin123` في الإنتاج) |
| `CLIENT_URL` | نطاقات مسموح لها بالاتصال، أو `*` أثناء التطوير فقط |
| `ALLOW_OFFLINE_MODE` | قراءة المنتجات من ملف JSON عند تعطل قاعدة البيانات (تطوير فقط) |

### 3. تعبئة قاعدة البيانات

```bash
npm run seed            # استيراد المنتجات (آمن للتكرار)
npm run seed -- --reset # حذف المنتجات والأقسام ثم الاستيراد من جديد
npm run indexes         # بناء الفهارس فقط
```

السكربت يستورد المنتجات المطابقة على `sourceId`، فإعادة تشغيله تحدّث الصفوف
الموجودة بدل إنشاء تكرارات. عند أول تشغيل على قاعدة بيانات فارغة يقوم الخادم
تلقائياً باستيراد الكتالوج، فلا حاجة لتشغيل `seed` يدوياً بعد النشر.

> السكربت يتجاهل المنتجات التي لا يوجد لها سعر، ويولّد روابط فريدة (`slug`) لكل
> منتج مع معالجة تكرار الأكواد في البيانات المصدرية.

### 4. تشغيل الخادم

```bash
npm start     # الإنتاج
npm run dev   # التطوير مع إعادة التشغيل التلقائي
```

المتجر ولوحة التحكم يُقدَّمان من: `http://localhost:5000`
وتولّد الاختبارات قاعدة بيانات مؤقتة، لذا لا تحتاج إلى MongoDB محلي للاختبار.

## 🧪 الاختبارات

```bash
npm test              # كل الاختبارات
npm run test:security # أمان المصادقة والتسعير
npm run test:customer # حسابات العملاء والسلة
npm run test:seeder   # سلامة الاستيراد (يتحقق من البيانات الحقيقية)
npm run test:env      # حراسة متغيرات البيئة في الإنتاج
```

تعمل الاختبارات على `mongodb-memory-server` الذي يُنزّل نسخة MongoDB حقيقية،
فتُختبر مسارات قاعدة البيانات فعلياً وليست محاكاة.

## 🔐 ملاحظات أمنية مهمة

- **الأسعار تُحتسب في الخادم دائماً.** لا يُقبل أي سعر من المتصفح؛ يُعاد تحميل
  كل منتج من قاعدة البيانات عند إنشاء الطلب.
- **لا يوجد تجاوز لصفحة الأدمن.** كل توكن يجب أن يقابل سجل `Admin` حقيقياً.
  لا يوجد تسجيل دخول من متغيرات البيئة.
- **CORS:** في الإنتاج يجب ضبط `CLIENT_URL` على النطاق الحقيقي؛ القيمة `*`
  تُرفض عند `NODE_ENV=production`.
- **حدود الطلبات:** تسجيل الدخول، إنشاء الحساب، إرسال الطلبات، والرسائل لكل منها
  حد خاص. الوضع المحلي (تطوير فقط) لا يفرض حدوداً حتى لا تتداخل مع الاختبارات.
- **Content-Security-Policy:** يمنع السكربتات المضمّنة، لذلك منطق لوحة التحكم
  في `frontend/admin/admin.js` وليس داخل `<script>` في الصفحة.
- **ملفات ثابتة محدودة:** يُقدَّم مجلد `frontend/` من قائمة سماح صريحة، فلا يمكن
  الوصول إلى `backend/` أو `data/` أو `.env` أو `render.yaml` من المتصفح.

## ☁️ النشر على Render

الملف `render.yaml` جاهز للاستخدام مباشرة من مستودع GitHub:

1. ارفع المشروع إلى GitHub.
2. في Render اختر **New → Blueprint** واربط المستودع. سيقرأ `render.yaml`.
3. املأ المتغيرات التي تحتاج قيمة منك:
   - `MONGODB_URI` — رابط MongoDB Atlas
   - `CLIENT_URL` — نطاق الموقع الحقيقي
   - `ADMIN_EMAIL` و `ADMIN_PASSWORD` — حساب لوحة التحكم
   - استخدم كلمة مرور قوية وفريدة، ولا ترفع `backend/.env` إلى Git. ينشئ Render
     قيمة `JWT_SECRET` عشوائية من `render.yaml`.
4. انشر، ثم اتبع قائمة التحقق في `DEPLOYMENT_SMOKE_CHECK.md`.

> **مهم:** `rootDir` هو جذر المستودع وليس `backend/`، لأن الخادم يقدم صفحات
> المتجر من `frontend/` ويقرأ ملف المنتجات من `data/`.

### ملاحظات على الخطة المجانية

- الخادم يتوقف بعد فترة عدم نشاط؛ أول طلب يعيد تشغيله.
- الصور المرفوعة محلياً تُحفظ في `backend/uploads/`. على Render يربط `render.yaml`
  قرصاً دائماً على `/var/data` ويحفظ الصور في `/var/data/uploads/`. في استضافة أخرى
  اضبط `UPLOAD_DIR` على مسار دائم قابل للكتابة قبل تفعيل رفع الصور.
- يوصى بخطة مدفوعة للثبات والأداء، أو MongoDB Atlas مجاني بمجموعة M0.
